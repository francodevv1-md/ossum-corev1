# Historical identity ledger — conceptual design, no schema applied

**Recommendation: staging + transversal ledger, NOT legacyId columns on every OSSUM entity.** Contact is global, Article scoped to Organization and Surgery to Company; different waves will reuse masters across runs. `CIRCOD ≠ Surgery.visibleNumber` (current number allocator produces `CX-####`), `CLICOD ≠ Contact.id/link.code`, `ARTCOD ≠ Article.id/sku` without match decision. Include a **stable source-system namespace** (`consultar-plus:districorr`, without backup date or wave), `companyId`, `entityType`, **lexical** `legacyId`; snapshot date/hash belongs to MigrationRun instead. Otherwise each new backup would bypass idempotency. Resolve company PRINC/TEST by explicit mapping. A global shared Article may be referenced from multiple company-specific refs mapping the same target Article.id; targetId must **not** be globally unique across refs.

Minimum durable conceptual tables before ANY write:

1. **MigrationRun**: id; sourceNamespace, sourceSnapshotHash (or table-hash manifest), cohort predicate (as JSON), strategyVersion, state (PLANNED/RUNNING/RECONCILED/FAILED/ROLLED_BACK/PARTIAL), startedAt/finishedAt, initiatedById. Keyed by id; retry creates a new run, never mutates an old outcome. No stale approval by old run.
2. **LegacyEntityRef**: id; `companyId,source,entityType,legacyId` unique **NOT NULL**; `targetEntityId NOT NULL`, `createdByRunId` nullable for native reused, `lastRunId`, `inputHash`, `sourceLoadedOn @db.Date?` for surgery, `ownership` MIGRATION_CREATED/NATIVE_REUSED, `status` IMPORTED/ROLLED_BACK, createdAt/updatedAt. **Create only after a target is actually CREATED/REUSED**; rejected/review cases live solely in MigrationRunItem, so they cannot poison the identity key or require undefined ownership. FK company and run. No global target uniqueness because multiple legacy codes can match one native target. Entity-type/target-table integrity enforced by typed resolver and reconciliation.
3. **MigrationRunItem** (instead of mutable error-only row): immutable `sourceRecordKey` (source table + physical ordinal) unique with `migrationRunId`, so even a row with **missing legacyId** can be logged. `legacyId` nullable; `(migrationRunId,companyId,source,entityType,legacyId)` is a NON-unique diagnostic index because **two source rows may have the same ID** (CLICOD 2268 / ARTCOD 1301-T1S) and both errors must be recorded. `action` CREATED/REUSED/UPDATED/SKIPPED/REJECTED, `status` SUCCESS/ERROR/REVIEW, beforeImage/diff for UPDATED, originalHash/transformedHash, ordered warning/error codes, targetId, timestamps. Persist per-attempt outcomes atomically with target and ref, including retries. Private error evidence sanitized; separate MigrationError only if volume/search justifies it. A MigrationReconciliationReport can be immutable artifact referenced by run hash, not necessarily a fourth table.

Idempotency unique identity **`(companyId,source,entityType,legacyId)`**; never add `migrationRunId` or `inputHash` to this key. A second run first looks up the key: same hash and strategy version => SKIPPED **only if target still exists, belongs to the intended company/organization, has expected ownership and has no conflicting native edits**; missing/changed target => REVIEW/REPAIR, never silently recreate or skip. Changed hash => diff + REVIEW unless a controlled update policy exists. Detail records, if later migrated, require stable parent-qualified IDs such as `STKCOD/MOVORD` with escaped separators and source company; do not cast numeric strings that might have leading zeroes. Upsert must be transactionally serialized on this unique key to prevent concurrent duplicate target writes. `sourceSnapshotHash` and transform version identify provenance; retries preserve canonical input byte hash or normalized documented hash including memo payload and encoding strategy.

Rollback for Run X: consult RunItem ownership, identify target created exclusively by X, and reverse-delete only after checking later-run references and native edits/foreign dependencies. REUSED/SKIPPED/REJECTED never delete; UPDATED needs before-image + optimistic version check and compensating event; otherwise mark BLOCKED_MANUAL_REVIEW. Contact/Article shared across surgeries remain if later dependent; partial rollback explicitly reported. Migration audit uses a controlled OSSUM User actor (AuditEvent requires userId); authorization and actor policy are **human approval boundary** before write, not bypassed by script.

No schema changes are necessary for read-only dry-run; before DEV write, three ledger tables (or equivalent atomic durable design) plus explicit sourceLoadedOn and approved date-only policy are minimum. No PostgreSQL or Prisma change is performed here.
