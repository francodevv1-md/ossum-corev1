# `migration:dry-run` v0 — executable contract, NOT an implementation

**Decision:** a future command can run **entirely read-only locally** now; DB matching is an optional separately authorized read-only adapter, not a hidden dependency. It must never invoke Prisma mutations, REST POST/PATCH/DELETE, side-effect services, migrations, fiscal issuance, or logs with PHI. It can write private derived reports only under `.tmp/consultar-plus-openai-audit/` (outside backup and ignored from Git). This document specifies behavior; `core_closure.py` is only a *targeted feasibility measurement*, **not** the migration command.

## Stable input and boundaries

CLI contract for **cohort run**: `migration:dry-run --source <read-only-backup-path> --source-namespace consultar-plus:districorr --company-map <private non-secret JSON> --cohort surgery-date:2026-06-01..2026-09-30 --out <private-temp-dir> --match-mode legacy-only`. A **separate** `--sample-only --sample <private fixture of 50+10 CIRCOD>` run disregards cohort filtering: the frozen 50 include 32 outside June–September and 2 from 2024. Both modes use the same normalization/validation, but different selection policies; `--cohort` and `--sample-only` are mutually exclusive. Future `--match-mode dev-read-only` requires verified DEV-only credentials supplied by environment, nonlogging; never connect by default. Same pipeline with `--cohort loaded:2026-01-01..2026-12-31` or successive years. Cohort is explicit, source snapshot file hashes verified **before processing** against manifest; mismatches STOP the run. The present `core_closure.py` feasibility probe does NOT implement that preflight.

1. Read only relevant DBF records; validate header/deleted markers and deterministic codepage; keep raw source fields, source table+record position+content hash, not raw PHI in public log. Decode FPT later only via read-only reader; unresolved memo gets WARNING.
2. Normalize civil dates and identifiers with field-specific rules, retain original representation + parser version; no timezone conversions that invent an observed hour.
3. Resolve Contact by `(companyId,source,Contact,CLICOD)` then candidate native matching only if read-only DEV adapter enabled. Ambiguous/orphan required patient => ERROR; optional missing refs => WARNING/REVIEW. Also resolve `CIRCLICOD` as a **fifth** commercial reference for reconciliation only; OSSUM Surgery has no verified field for it: preserve as source-only, never overwrite payer.
4. Article is **optional** for Surgery core. Independently resolve catalogue or report article dependencies without loading STOCK1 into OSSUM. Article absence cannot reject a core Surgery.
5. Construct `LegacySurgeryRecord` with source fields CIRCOD, CIREMPCOD, CIRFECCAR/CIRFEC/CIRFECLOG, CIRESTADO, all **five** contact refs including CIRCLICOD, CIRTIP/VIACOD/AUSRID/auth/memo pointers; verify source status and tenant.
6. Validate -> `SurgeryCandidate`: resolved tenant/contact IDs (or abstract handles in legacy-only mode), sourceLoadedOn civil date, surgeryDate civil date, materialShippingDate civil date, cxStatus candidate or REVIEW, prepStatus=null, visibleNumber=null, performedDate=null, source marker. **Do not instantiate a write payload when required native targets are unknown.**
7. Output per source record: `{source,companyCode,entityType,legacyId,sourceHash,cohortMembership,eligibility,contactResolution:{patient,doctor,institution,payer,commercialSourceOnly},articleResolution:{mode,counts,exceptions},dateMapping:{sourceLoadedOn,surgeryDate,materialShippingDate},statusMapping:{raw,cxStatus,prepStatus,losses},warnings:[code],errors:[code],wouldCreate:null|boolean,wouldReuse:null|boolean,existingTargetId:null|id,action:REVIEW|REJECTED|UNRESOLVED_NATIVE|PROPOSE_CREATE|PROPOSE_REUSE|SKIPPED}`. In legacy-only mode wouldCreate/wouldReuse **null** and structurally eligible records are `UNRESOLVED_NATIVE`, not speculative PROPOSE_CREATE. The record-level report contains pseudonymous CIRCOD and must remain access-controlled; no names, DNI/CUIT or clinical text in the aggregate/public report.
8. Report aggregate sourceTotal, selected, excludedDeleted, duplicates, eligible, rejected, review, warning-only, nativeMatched, proposedCreate/Reuse, skipped, unresolved; compare all selected IDs and vital fields vs source. Assert `selected = eligible + rejected + review` with disjoint groups; `eligible = proposedCreate + proposedReuse + skipped + unresolvedNative`. `REVIEW` is reserved for unresolved source semantics/collisions, NOT ordinary missing DEV adapter. Report hash of report, source manifest, parser/strategy version and timezone/date policy; exit nonzero for corrupt source/hash mismatch, not for expected per-row rejects.

**Required acceptance tests:** deterministic rerun identical source hashes and candidate IDs/status counts; no DB connections in legacy-only mode; source files byte hash unchanged; **sample-only** run includes all 50 positives and all 10 negatives with required ERROR/WARNING. The **June–September cohort** contains only the 16 positive fixture members dated in that window; do not assert 50. No row silently omitted or duplicated; no current OSSUM entity creation. Missing DEV match is `UNRESOLVED_NATIVE`, never `wouldCreate=true` by assumption. A DEV-match phase additionally proves company-scoped native reconciliation; it remains pending and must never use real/staging credentials.
