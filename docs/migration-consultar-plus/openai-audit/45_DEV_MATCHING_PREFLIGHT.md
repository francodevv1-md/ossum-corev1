## Contrato conceptual del adapter (no implementado)

`DevReadOnlyResolver` se instancia **únicamente** con `--match-mode dev-read-only` después de una verificación externa de A/B/C/D; recibe conexión SELECT-only dedicada y empresa objetivo explícita. Métodos: `resolveCompany(sourceCompanyCode)`, `resolveOrganization(companyId)`, `matchContacts(companyId, candidates)`, `matchArticles(organizationId, candidates)`, `findPotentialSurgeryDuplicates(companyId, candidates)`. Interfaz separada de services/Prisma productivos y del lector DBF. Las consultas no deben generar/mutar `ContactCompanyLink`, roles ni Articles; `BEGIN READ ONLY` es defensa adicional, **no sustituto** del rol SELECT-only.

Clasificar contactos por documento validado + compatibilidad persona/empresa + vínculo Company; nombre solo evidencia secundaria. Article por organización, SKU/ArticleIdentifier confiable y contexto de fabricante/proveedor, descripción secundaria; ARTCOD no es SKU automáticamente. Surgery solo como *posible* colisión combinando paciente, fecha civil, médico, institución, pagador, clasificación y tenant; paciente+fecha aislados nunca equivalen a identidad. Salidas EXACT_REUSE/POSSIBLE_REUSE/AMBIGUOUS/NO_MATCH/CONFLICT/UNMATCHABLE; `NO_MATCH` **no autoriza CREATE**. Si el schema activo incorpora nuevas columnas de Article, el adapter deberá seleccionarlas únicamente cuando sean necesarias y verificadas; no extrapolar documentos antiguos a la DB actual.

**Desbloqueo exacto:** obtener identidad DEV descartable actual + evidencia de credencial DB efectivamente SELECT-only + Company/Organization PRINC identificados y garantía de no producción. Sin uno de estos cuatro elementos, no conectarse. Ningún modelo Prisma, writer ni write test forma parte de Gate 2.
