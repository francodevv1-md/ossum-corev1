## 3. Canonical rendering and parser contract

The following templates are AST templates, not executable SQL. A later generator must render them with exact quoted physical names from `C13`, uppercase keywords, `"public"` qualification, `LANGUAGE plpgsql VOLATILE SECURITY INVOKER SET search_path = ''`, UTF-8/NFC/LF, no trailing horizontal whitespace, and one terminal LF.

- `CHK(R,N,P)`: `ALTER TABLE "public"."R" ADD CONSTRAINT "N" CHECK ((P) IS TRUE);` with the canonical multiline style used by passed CX proposals. `P` is the exact predicate in the object row below; enum literals use their physical PostgreSQL labels from `C13`.
- `APP(F)`: the passed 23-LF append-only function shape: unconditional U01-A/TEI R0001 `23514` raise; function-specific invariant, function, message ID, `APPEND_ONLY`; no `RETURN` path.
- `GUARD(F,V,D)`: one complete trigger function. Declarations/queries `D` compute Boolean `V`; `IF V IS TRUE THEN RETURN NEW; ELSE` emit exactly one TEI R0001 raise with the row's family and `END IF;`. No implicit success, dynamic SQL, ambient `search_path`, mutation, advisory lock, or projection authority.
- `TRG(T,R,F,E)`: `CREATE TRIGGER "T" E ON "public"."R" FOR EACH ROW EXECUTE FUNCTION "public"."F"();`. Append-only `E=BEFORE UPDATE OR DELETE`; ordinary guards use U02-A `BEFORE INSERT OR UPDATE`.

For **every** object row below, the later writer must produce: one complete object fragment; one OBJECT/OBJECT_INVENTORY owner; full declaration/body SOURCE_SPAN and LOCATOR; exact parser-extracted Boolean roots, ATM leaves and occurrences; every decision point/outcome/BRN/action/error; complete unique DT edges with every source occurrence; and exact EVT rows. `none` means the proven empty set, not deferred work. Locators are block-local half-open UTF-8 spans and use the P19 raw/LF/normalized hash rules. Parser equality is mandatory: parsed sets must equal authored inventories in both directions; an unsupported token, hidden Boolean, unresolved owner, inferred dependency, or unclassified branch stops.
