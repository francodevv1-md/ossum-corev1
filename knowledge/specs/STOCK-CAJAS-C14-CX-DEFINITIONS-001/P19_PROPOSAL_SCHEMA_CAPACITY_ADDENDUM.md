## 3. Four-class profile and common scalar contract

The directory remains exactly:

```text
canonical-sql-v1-proposal/profile.cj1
canonical-sql-v1-proposal/blocks/CXnn/dddd.sqlfrag
canonical-sql-v1-proposal/proposal-rows.cjl1
canonical-sql-v1-proposal/proposal-root.cj1
```

No other file or path class is valid. The byte rules, CJ1/CJL1 rules, `.sqlfrag` content rule, and `CXnn/dddd` ordering in A01–A06 remain unchanged. Unknown or duplicate JSON keys, absent required keys, JSON `undefined`, floating point, non-canonical JSON, and unlisted enum values fail.

CJ1 string encoding is parent P02 exactly: quotation mark and reverse solidus use `\"` and `\\`; every U+0000–U+001F code point uses one lowercase six-byte escape `\u00xx`. JSON short escapes `\b`, `\f`, `\n`, `\r`, and `\t` are forbidden even when an ordinary JSON parser would accept them. Every normative CJ1/CJL1 example in this addendum obeys that byte rule.

Every field listed below is required. `T|null` is the only nullable form; there are no omitted optional fields. Arrays are always present. Empty arrays are valid only where stated. Array order is semantic and specified below; duplicates are forbidden unless expressly stated otherwise.

Scalar domains are the parent P02 domains, with these closed refinements:

- `Hex40`, `Hex64`, `UInt`, `PosInt`, `NString`, `RepoPath`, `Cx`, `C14Child`, `ObjectId`, `PhysicalRelation`, `PhysicalColumn`, and `UtcMillis` are exactly parent P02. Validation is semantic, not merely regex matching.
- `GlobalOrCx` is `null` for global rows or one literal `CX01..CX13`.
- `Ordinal4` is a `PosInt` `1..9999`; its path rendering is exactly four ASCII decimal digits with leading zeroes.
- `ProposalRowId` is `C14P2-GLOBAL-<KIND>-dddd` for global rows or `C14P2-CXnn-<KIND>-dddd` for CX rows, where `<KIND>` is exactly the row kind below and `dddd` is the contiguous per `(GlobalOrCx,KIND)` ordinal.
- Semantic IDs use the row's CX and contiguous source/canonical order: object IDs remain parent `ObjectId`; body `C14PB-CXnn-dddd`; Boolean node `C14PN-CXnn-dddd`; expression root `C14PE-CXnn-dddd`; atom `C14PA-CXnn-dddd`; occurrence `C14PO-CXnn-dddd`; loop `C14PL-CXnn-dddd`; extension decision point `C14PG-CXnn-dddd`; function decision point `C14PD-CXnn-dddd`; outcome `C14PU-CXnn-dddd`; branch `C14PR-CXnn-dddd`; action `C14PX-CXnn-dddd`; error `C14PF-CXnn-dddd`; dependency `C14PY-CXnn-dddd`; event `C14PV-CXnn-dddd`; locator `C14PQ-CXnn-dddd`; source span `C14PS-CXnn-dddd`; provenance `C14PP-(GLOBAL|CXnn)-dddd`; evidence `C14PW-GLOBAL-dddd`; proposal decision `C14PC-GLOBAL-dddd`; alternative `C14PT-GLOBAL-dddd`; inventory `C14PI-CXnn-dddd`; attachment `C14PH-CXnn-dddd`; owner `C14PK-CXnn-dddd`; physical identifier `C14PM-CXnn-dddd`; seed source `C14PZ-CXnn-dddd`.
- `PgName` is NFC, contains no NUL/C0 control, and its UTF-8 encoding is `1..63` bytes. It is the exact PostgreSQL identifier content before quoting. `quote(PgName)` is ASCII `"`, then each embedded `"` doubled, then ASCII `"`.

A field ending only `Id` is a semantic ID in the grammar above and never a row reference. Reference arrays are ordered as stated and contain no duplicate ID. This naming rule eliminates context-dependent ID overloading.

## 4. One V2 closed tagged-union row model

`ProposalRowCore(V)` is the exact keys of the selected variant `V` except `rowSha256`. `ProposalRow(V)` adds only `rowSha256:Hex64`. Every variant begins with `{schemaVersion:"C14P-ROW-V2",rowId:ProposalRowId,kind:<literal>,cx:GlobalOrCx,ordinal:Ordinal4,...}`. `ordinal` and `rowId` must agree. No variant's fields may appear on another variant.

`ProposalFragmentRef` is exactly `{fragmentPath:RepoPath,byteLength:PosInt,fragmentSha256:Hex64}`. The path names one `.sqlfrag` in the four-class profile, length is its exact byte length, and hash is §5 `fragmentSha256` over those bytes. It is proposal-local, non-authoritative, immutable under one proposal root, and contains no row or root digest, so it cannot create a cycle.

Rows are ordered by `(scopeRank,cxRank,kindRank,ordinal,rowId bytes)`, where global scope rank is 0, CX scope rank is 1, CX rank is `01..13`, and kind rank is the following table order. This order fixes 26 row kinds and **27** closed variants because EVIDENCE has two subvariants.
